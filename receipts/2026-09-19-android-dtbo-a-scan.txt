Read-only Android DTBO A-slot scan
==================================

  ro.product.device=kalama
  ro.build.fingerprint=qti/kalama/kalama:13/TKQ1.231222.001/eng.RPN.20260722.081626:user/release-keys
  ro.boot.slot_suffix=_a

Partition read:
  Source: /dev/disk/by-partlabel/dtbo_a on the Nova while booted into Linux
  Method: read-only dd over SSH; no target partition or boot state was written
  Partition bytes copied: 25,165,824

Property paths are fragment@28/__overlay__ for index 49, fragment@30/__overlay__
for indices 50-52, and fragment@42/__overlay__ for indices 53-55. Index 51
also contains qcom,no-client-based-bw-voting in the same overlay fragment.

Index 51's root match data exactly matches the public RP6 Android DT source:
qcom,msm-id = <603 0x20000> (603 decimal is 0x25b) and
qcom,board-id = <0x1001f 0>. Its model string says KalamaP HDK. The overlay's
fragment@30 target is an unresolved phandle placeholder in the blob; its
__fixups__ mapping and the bootloader's selected-overlay result still need to
be resolved. This makes index 51 the strongest candidate, not proof that it
was selected or that the property was present in the merged runtime DT.

Correction history: the first read of this header reversed dt_entry_count and
dt_entry_size and incorrectly described 32 entries of 56 bytes. AOSP's header
order and this bounded reparse establish the correct values above: 56 standard
entries of 32 bytes. No device state was changed during either read.
