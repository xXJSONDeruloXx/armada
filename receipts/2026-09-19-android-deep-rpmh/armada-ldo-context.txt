These are active-state mode changes around suspend/resume; they are not
sleep-state requests. Across the available archived Linux raw trace text,
there are no requests to LDOE1 enable (0x43904) or LDOE3 enable (0x43a04), and
no [sleep]/[wake] requests to either LDOE resource. The active LDOs are put in
mode 4 before suspend and returned to mode 7 on resume. They are not disabled
in the captured Linux request stream.

The corresponding Android simpleperf capture stages a separate SLEEP set with
LDOE1 mode 4 and both LDOE1/LDOE3 enable 0, then a WAKE set with LDOE1 mode 7
and both enables 1. Android's active FDT sets the relevant qcom,set sleep bits
on its -so proxy regulators. This is a source-backed request-policy delta.
It is not yet proof that the missing Linux sleep votes cause AOSD/CXSD/DDR
firmware counters to remain zero; RPMh tracepoints show requests, not final
firmware residency.
